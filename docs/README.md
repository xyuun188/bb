## 历史文档

历史整改计划、验收记录、旧台账和旧系统快照统一放在 [`archive/`](./archive/)。它们保留用于审计追溯、问题复盘和了解历史决策，**不作为当前状态、当前计划或当前验收依据**。

## 引用规则

1. 新的整改、验收和进度判断，先引用当前唯一整改基线，再引用代码、测试和线上证据。
2. 需要解释历史背景时，明确标注“历史归档”，并给出具体日期。
3. 新文档必须写明编制日期、文档状态（当前有效/历史归档）和适用范围。
4. 旧文档与当前代码或当前整改基线冲突时，以当前代码、测试结果和最新基线为准。
5. 不在 `docs` 根目录重新创建未标状态的整改计划；新的计划应先更新当前基线或经过确认后替换它。
