# 线上系统全面复查与训练效果可视化整改计划

**日期：** 2026-08-26  
**状态：** 待审核，尚未执行  
**范围：** 线上量化平台、模型服务隧道、分析/开仓/平仓执行链路、训练调度、训练效果页面、系统巡检

## 1. 计划目的

本计划不是单独放宽开仓门槛，也不是把页面上的“不可用”文字改成“可用”。目标是建立一条可验证、可回放、不可重复误判的闭环：

```text
行情/持仓事实 -> 分析与专家调用 -> 交易合同 -> OKX 请求/成交
             -> 结算与资金费/手续费 -> 权威收益标签 -> 训练/评估
             -> active/challenger 对照 -> 页面事实展示 -> 晋升或拒绝
```

任何一环没有权威证据时，系统必须明确显示“证据缺失/观察中”，不能把它伪装成模型服务故障，也不能把影子样本当作真实盈利。

## 2. 本次线上复查确认的事实

### 2.1 模型与训练服务

- `/api/ml-signal/status` 当前可访问，`available=true`，但整体 `status=degraded`，`live_ml_ready=false`；Paper Canary 已授权，当前只允许模拟盘参与，不能影响实盘。
- 当前主 Artifact 为 `20260822T100531912797Z-cf8ed1c9`，训练时间为 2026-08-22 10:05 UTC。
- 当前训练窗口约有 93,549 个 shadow 样本、207 个训练交易样本，另有约 9,103 个新增 shadow 样本尚未进入下一次训练。
- 晋升阻断是真实收益证据问题，不是模型文件加载失败：多空方向的 LCB、Profit Factor、时间滚动稳定性、跨行情状态稳定性和留一币种稳定性均未满足条件。
- 注册表中 `local_ml_profit_quality` 为 `promotion_blocked`；多个 Local AI 专家为 `canary`；TimesFM、Chronos、FinBERT 及部分大模型角色为 `inference_only`，没有权威收益评估，不能据此判断训练成功或失败。
- 训练调度接口可用，但最近结果多为 `reason=not_due`。页面必须区分“没有到训练条件”和“调度器失效”。

### 2.2 模型服务与子接口

- Phase 3 量化 API、风险模型、FinQuant 专家接口当前可用；决策模型使用线上 DeepSeek 路由，18000 端口的 Qwen 备用路由不是必需阻断项。
- 量化隧道近期多次出现短暂健康检查超时后恢复，说明需要延迟/超时趋势监控，不能只看单次 `active`。
- 本地 AI 状态接口中的四个子接口目前主要是 `metadata_contract`，`actual_inference_probe=false`。这表示“接口和模型产物已登记”，不等于四个子接口都完成了真实推理探针。
- 截图中的“服务不可用/真实子接口 0/4”与当前后端 `available=true` 不一致，必须排查页面缓存、请求超时、接口状态语义混用和旧状态保留。

### 2.3 系统巡检与交易链路

- 当前巡检为 27 个卡片：6 个 critical、4 个 warning、17 个 ok。
- 未闭环项包括：Paper 恢复前置检查、Paper 恢复观察、动态收益策略闭环、交易执行合同、Phase 3 go/no-go、阶段交接，以及 OKX/本地交易事实告警。
- 最近运行窗口检测到 2 个执行合同违规：`external_okx_close_fill_lifecycle_not_unique`、`executed_exit_without_filled_order`。这两个问题必须先完成生命周期对账，不能只改巡检文字。
- 最近窗口 500 个决策中有 7 个入场决策、4 个已执行入场、8 个退出执行；多头入场占比约 85.7%，超过 80% 集中度告警阈值。该指标只能作为诊断，不能被改成强制配额或直接放宽风控。
- OKX 事实完整性卡片的 34 条记录主要是 `superseded_position_residual` 信息级残留，另有 2 个当前阻断候选。信息级历史残留应与当前阻断分开呈现，不能混成同一个“系统异常”。
- 服务器资源当前不是根因：平台服务器内存约 21.9% 使用率，磁盘约 45%；模型服务器 GPU 可用，但显存约 73% 已使用。仍需保留资源峰值和推理延迟监控。

## 3. 整改目标与边界

### 3.1 必须达到的目标

1. 页面能分别回答：服务是否在线、模型产物是否存在、是否做过真实推理、训练是否成功、评估是否完成、是否允许模拟盘、是否允许实盘。
2. 页面能显示 active、最新 challenger、无模型基线三者的同口径对照，包括手续费、滑点、资金费、净收益、LCB、Profit Factor、回撤、方向、币种和行情状态。
3. 每笔决策可追踪到：信号、证据门禁、风险合同、订单提交、成交、持仓、平仓、结算、训练标签；失败必须标明发生在哪一层。
4. 2 个执行合同违规和 Paper 恢复/阶段交接阻断完成闭环后，巡检才能从 critical 降级或清除。
5. 训练调度不再因为“not_due”被误报为故障，也不再以重复训练制造“训练有进展”的假象。
6. 所有验收均采用一次性、带运行 ID 的有界检查；禁止无限轮询、重复触发训练或重复写入审计记录。

### 3.2 明确不做的事

- 不因开仓少而直接放宽收益、风险或证据门禁。
- 不把影子机会样本当作真实盈利，不用历史残留伪造成功成交。
- 不把备用 Qwen 路由的不可用当作必需服务故障。
- 不在未完成真实成交样本外验证前晋升模型。
- 不在本计划审核前修改线上代码、训练参数、模型路由或交易权限。

## 4. 分阶段整改工作流

### W0：建立一次性基线与证据快照

- 生成带 `audit_run_id`、时间窗口、代码版本、Artifact 版本、训练游标和数据库快照指纹的只读报告。
- 固定当前 active 模型、最新 challenger 和无模型规则基线，后续所有指标只从同一窗口和同一成本口径计算。
- 记录服务器、数据库、Redis、OKX、18000-18003 隧道和量化 API 的状态与延迟。
- 验收：同一 `audit_run_id` 重复查看不会新增训练、订单、数据库写入或重复巡检记录。

### W1：拆分模型服务状态合同

统一定义以下状态，不再用一个 `available` 字段覆盖所有含义：

- `transport_status`：网络、端口、HTTP 健康。
- `artifact_status`：模型包、元数据、指纹、版本兼容性。
- `inference_probe_status`：真实最小推理探针是否成功、延迟和错误码。
- `training_status`：调度器是否运行、最近一次结果、`not_due` 原因、下次检查时间。
- `evaluation_status`：样本外、滚动、留一币种、行情状态和权威成交收益证据。
- `permission_status`：shadow、Paper Canary、实盘候选、实盘 active。

子接口显示必须区分 `metadata_ready`、`live_probe_ok`、`degraded`、`unavailable`。四个接口没有真实探针时，不得显示为“0/4 服务不可用”，而应显示“4/4 已登记，真实推理探针未执行”并标明原因。

### W2：修复训练效果可视化闭环

在“本地 ML”和“训练”页面增加只读的事实面板：

- **版本链：** 最新训练版本、最新评估版本、当前 active、候选 challenger、距 active 的时间/版本差。
- **样本链：** shadow 市场机会、反事实成本、OKX 实际成交、资金费、手续费、平仓收益；显示 train/holdout/OOS 数量及时间范围。
- **结果对照：** 无模型基线、active、challenger 的平均费后净收益、LCB、Profit Factor、胜率（仅诊断）、最大回撤、CVaR、样本数。
- **分层结果：** 多/空、币种、持仓时长、行情状态、专家/模型角色。
- **归因链：** 模型判断错误、证据门禁拦截、订单未成交、过早部分平仓、手续费/滑点、资金费归因、OKX 对账失败分别统计。
- **晋升判定：** 每个阻断码显示实际值、目标值、证据时间窗和对应版本；明确“训练完成”不等于“晋升通过”。
- **调度时间线：** 训练开始、结束、跳过、失败、`not_due`、下次检查，避免页面只显示一个模糊的“训练中/未训练”。

所有卡片必须显示数据时间戳、来源和新鲜度；接口异常时保留上次数据但显式标记 `stale`，禁止将旧数据渲染为当前在线事实。

### W3：闭合交易执行合同

- 对 2 个当前违规逐笔建立生命周期：决策 ID、symbol、side、OKX posId、入口订单、退出订单、成交数量、平仓时间、结算时间。
- `executed=true` 必须有可验证的 filled order；外部 OKX 平仓必须能唯一映射到一个生命周期，否则保持 `unverified` 并阻止训练标签进入权威集合。
- 检查动态平仓比例、持仓经济学、风险预算、计划损失、名义价值、最小下单量、杠杆和成本合同是否来自同一版本指纹。
- 将“执行合同违规”与“策略没有收益”分开统计；合同未闭合时不得把收益反馈给模型。
- 验收：当前窗口违规数为 0；每个已执行入场/退出均有非零成交证据和唯一生命周期；历史残留仍保留但不再冒充当前阻断。

### W4：完成 Paper 恢复与阶段交接

- 明确 `requires_operator_start` 的操作边界：巡检只读，不自行恢复交易服务，不自动改变模型路由。
- 生成一次恢复前置报告和一次固定观察窗口报告，包含心跳、分析轮次、订单、成交、错误、内存、延迟和 OKX 同步。
- 观察窗口结束后只允许三种结论：通过并进入下一阶段、继续观察并给出剩余证据、阻断并列出根因；禁止长期停在“观察中”而没有出口。
- `go_no_go`、`stage_handoff`、`paper_resume_preflight`、`paper_resume_observation` 必须引用同一份报告指纹，避免卡片之间互相矛盾。

### W5：恢复训练调度和训练数据治理

- 将“新增样本不足”“未到训练周期”“标签未结算”“权威身份未确认”“训练任务失败”拆成不同状态和计数。
- 训练只消费完成且权威的生命周期；资金费、手续费、滑点和浮动/平仓收益必须在标签中明确归因。
- 同一 decision group 不得重复进入 train 和 holdout；新增样本不足时只更新游标和报告，不重复加载全量特征。
- 每次训练必须绑定一个可复现实验假设，例如修正资金费标签、退出标签或执行成本；没有假设和对照结果不得启动训练。
- 验收：调度器能解释最近一次未训练的原因；训练报告能显示新增有效信息量；重复检查不产生重复训练任务。

### W6：整理系统巡检语义与页面布局

- 将问题分为 `当前阻断`、`需要关注`、`历史观察`、`已修复`、`信息级残留`，显示数量和进入/退出条件。
- `superseded_position_residual` 等信息级记录不得显示为红色当前故障；当前阻断候选必须单独列出对象、证据和处理动作。
- 每张卡片只保留一个主结论、一个根因、一个下一步；长列表支持展开详情，避免把完整 JSON 直接塞入卡片造成难读和错觉。
- 对 API 超时、缓存旧数据、前端请求失败分别显示，不把“接口超时”写成“模型未训练”。
- 验收：刷新页面多次不重复添加卡片；同一根因只出现一次；桌面和移动宽度下无文本重叠。

### W7：受控上线与回归验收

- 先上线只读状态合同和页面，再上线执行合同修复，最后才允许训练/晋升相关变更；每阶段独立版本和回滚点。
- 每阶段只执行一轮最小相关测试、一次线上只读探针和一次固定时间窗观察，不启动无界的全量训练或压力测试。
- 上线后至少观察：模型接口延迟/错误、分析轮次间隔、订单成交确认、平仓唯一映射、资金费归因、训练游标变化和内存峰值。
- 未满足验收条件时保持 Paper/Shadow，不切换实盘权限。

## 5. 统一验收标准

### 服务与接口

- 必需端口 18001、18002、18003 连续观察窗口内健康；18000 作为非必需备用路由单独标记。
- 量化 API、模型 Artifact 和真实最小推理探针的状态一致；不得出现后端可用而页面显示不可用且无 `stale/timeout` 解释。
- 训练页面请求在固定预算内完成，超时后显示可诊断错误并保留新鲜度，不重复发起同一请求。

### 交易与对账

- 执行合同违规为 0；执行成功的订单必须有非零成交数量、OKX 订单号和唯一生命周期。
- 当前 OKX 权威同步无未解释阻断；信息级历史残留不计入当前故障。
- 平仓收益、手续费、资金费和滑点可逐笔重算，且与 OKX 权威事实一致。

### 训练与晋升

- 页面能看到 active/challenger/无模型基线的同口径净收益和差值。
- 每个模型显示训练版本、评估版本、active 版本、晋升/拒绝原因和证据时间窗。
- 没有正的样本外费后优势、正 LCB、稳定 Profit Factor 和完整权威成交证据时，必须保持 `promotion_blocked` 或 Paper Canary。
- 训练任务只有在新增有效信息达到策略要求时才运行；`not_due`、等待结算和真实失败不能混为一谈。

## 6. 防止重复工作和半成品上线

1. 每个整改项建立唯一 `issue_key` 和 `audit_run_id`；已完成项再次检查只能更新状态，不能创建副本。
2. 每个长任务设置总超时、阶段超时和最大重试次数；超时后记录阶段和原因，不自动无限重跑。
3. 线上验证分为只读探针、模拟盘行为验证、训练数据验证三类，三类都通过后才可以标记完成。
4. 代码、数据库、模型 Artifact、页面资源分别有版本指纹；页面不允许用旧缓存数据覆盖新状态。
5. 任何影响交易权限、模型路由、仓位大小、杠杆或训练标签的变更，必须先通过本计划的对应验收项，并保留回滚点。

## 7. 执行顺序与交付物

执行顺序固定为：`W0 -> W1 -> W2 -> W3 -> W4 -> W5 -> W6 -> W7`。每个阶段交付一份短报告，包含：变更文件、线上版本、运行 ID、测试结果、未完成项和回滚方式。

本计划审核通过后，才进入代码修改；审核前不修改线上逻辑、不触发训练、不切换模型权限、不删除历史记录。
