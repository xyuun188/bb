# BB AI 量化系统模拟盘权限与训练闭环整改方案

日期：2026-07-27

项目：`E:\code\bb`

状态：本地实施完成，待线上自然交易闭环验收

适用范围：OKX 模拟盘交易、模型持续训练、模型晋升、OKX 实盘权限边界、Dashboard 治理展示

## 1. 文档目的

本方案整合以下两部分内容：

1. 用户提出的核心原则：模型晋升只控制 OKX 实盘权限，不控制 OKX 模拟盘交易权限。
2. 对该原则的工程补充：取消模拟盘晋升门槛的同时，必须保留硬风险、事实完整性、决策血缘、选择偏差记录和训练数据分层，避免把“允许采样”实现成无规则下单或不可归因训练。

本方案用于解决当前循环依赖：

```text
没有晋升
-> 不能参与模拟盘交易
-> 没有真实成交、手续费、滑点、持仓和平仓样本
-> 训练和晋升证据不足
-> 继续不能交易
```

整改后的闭环应为：

```text
可用模型持续分析
-> 统一决策层形成可审计方向
-> 模拟盘普通质量检查和硬风险检查
-> OKX 模拟盘正常交易
-> 正常持仓管理和平仓
-> OKX 权威成交与结算
-> 盈利和亏损样本共同训练
-> 独立评估模型晋升
-> 只有 OKX 实盘逐笔检查晋升和生产门禁
```

## 2. 当前问题与已确认根因

当前长期不开仓不是行情分析停止、服务中断或没有正向候选，而是多层治理合同共同阻断。

最近一次线上审计的 60 分钟窗口内：

- 市场分析 63 条。
- 扣除估算成本后，模型均值为正的方向 38 个。
- 最终开仓决策 0 个。
- `paper_exploration` 合同 0 个。
- `support_ready_side_count` 始终为 0。
- 趋势专家和盈利质量专家 63 次全部输出 HOLD。
- 服务进程正常，未发生重启或服务级告警。

已确认的系统性原因：

1. `entry_direction_support` 要求至少两个 LLM 专家同向肯定，专家 HOLD 被实际解释为否决。
2. `paper_exploration` 要求未晋升候选接近生产晋升统计水平，仍然依赖收益下界和信息价值。
3. `entry_profit_risk_sizing` 在探索路径中继续读取 production-only 分布和生产样本条件。
4. `trade_execution_contract` 在最终执行前再次校验旧探索语义，形成二次阻断。
5. 原 `paper_training` 已包含极小风险、持仓身份、结算和训练回流框架，但执行权限被写死为退役。
6. 权威训练事实链已经能够接收模拟盘真实成交，当前核心缺口是没有新的真实订单进入闭环。

因此，本次整改不能只调整一个布尔值或删除一个判断，必须同时修改模拟盘入口、决策支持、仓位计算、执行合同、订单身份和训练回流。

## 3. 最终业务原则

### 3.1 权限原则

模型生命周期状态与交易账户权限必须解耦：

- 模型生命周期描述模型证据成熟度。
- 模拟盘权限决定模型是否可以参与 OKX demo 交易。
- 实盘权限决定模型是否有资格影响真实资金订单。
- 模型晋升只授予实盘候选资格，不授予绕过逐笔风险检查的权力。

最终原则：

> 所有状态有效且能够给出可审计方向的模型，都拥有 OKX 模拟盘交易资格；模拟盘通过独立的普通交易质量与硬风险门禁执行，不检查晋升统计。模型晋升仅授予 OKX 实盘候选权限，实盘订单仍须逐笔通过生产门禁。

### 3.2 推荐权限矩阵

| 模型状态 | 市场分析 | OKX 模拟盘正常交易 | 参与训练 | OKX 实盘 |
| --- | --- | --- | --- | --- |
| Candidate | 是 | 是 | 是 | 否 |
| Shadow | 是 | 是 | 是 | 否 |
| Paper Canary | 是 | 是 | 是 | 否 |
| Active | 是 | 是 | 是 | 通过逐笔生产门禁后允许 |
| Degraded | 是 | 有条件允许并缩小影响 | 是 | 否 |

`Degraded` 必须区分两类情况：

- 模型表现降级：允许继续分析和训练，可在更小仓位、更低权重下参与模拟盘。
- 行情、账户、执行链或模型制品失效：禁止下单，直到硬故障恢复。

### 3.3 不可突破的边界

- 模拟盘取消晋升门槛，不等于每轮强制开仓。
- 模型不能绕过账户、合约、仓位和组合风险直接下单。
- 任何模型状态都不能绕过价格时效、重复订单、最小下单量和保护单检查。
- 不允许用默认手续费、默认滑点或伪造资金费补齐训练事实。
- 不允许把未成交订单和风控拒单冒充真实盈亏样本。
- 不允许因交易亏损而隔离事实完整的样本。
- 不允许通过多个角色包装同一个底层模型，制造虚假的独立专家共识。

## 4. Paper 与 Live 的门禁边界

### 4.1 模拟盘不得检查的条件

在 `trading_mode=paper` 时，不得把以下条件作为开仓前置条件：

- `live_ml_ready`
- 模型是否已经晋升
- 是否存在 production-grade 收益来源
- 生产样本数量是否成熟
- Profit Factor 晋升门槛
- 正收益 LCB 晋升门槛
- `production_trade_gate`
- production-only 收益分布
- production-only 执行成本分布
- 是否已经证明长期盈利

这些条件只能用于：

- 模型晋升评估。
- OKX 实盘候选资格。
- OKX 实盘逐笔生产门禁。
- Dashboard 的实盘就绪度说明。

### 4.2 模拟盘必须保留的硬检查

模拟盘仍必须检查：

- 实时行情有效且价格未过期。
- 合约规格来自 OKX 权威公开接口。
- 模型或统一决策层给出明确的 long/short。
- 决策身份、模型版本和预测期限完整。
- OKX demo 账户状态正常。
- 当前持仓和活动订单状态可确认。
- 最大持仓数量。
- 单币种、单方向和组合暴露上限。
- 最大单笔风险和最大组合风险。
- OKX 最小合约数量和数量步长。
- 重复订单、重复方向和冷却时间。
- 流动性和极端波动硬保护。
- 下单前保护策略可以建立。
- 数据、账户或执行链发生硬故障时失败关闭。

新闻数据通常不是通用硬门槛。新闻缺失可降低相关模型权重或置信度；只有明确依赖新闻的策略才可以把新闻有效性设为自身条件。

### 4.3 实盘专属检查

在 `trading_mode=live` 时，除全部硬风险外，还必须检查：

- 当前模型或策略已获得生产候选资格。
- `live_ml_ready=true`。
- 晋升合同版本有效。
- production-grade 权威结果数量成熟。
- 收益下界、Profit Factor、回撤、尾部风险和稳定性达标。
- 实盘执行成本分布完整。
- 当前订单通过 `production_trade_gate` 逐笔授权。

任何 paper 路径调用 `production_trade_gate` 都应被视为代码合同错误，记录明确诊断并阻止错误路径继续执行。

## 5. 统一模拟盘交易身份

### 5.1 取消业务分裂

退役以下模拟盘执行身份和独立执行分支：

- `loss_tolerant_paper_training`
- `paper_exploration`
- `training_sampling_order`
- 其他仅因“未晋升”而创建的特殊下单通道

所有新模拟盘订单统一为：

```text
trade_mode=paper
entry_type=normal_strategy_trade
production_permission=false
```

所有新模拟盘订单共用：

- 同一分析链。
- 同一决策链。
- 同一风险引擎。
- 同一执行服务。
- 同一持仓管理。
- 同一平仓管理。
- 同一 OKX 权威结算链。
- 同一训练事实入口。

### 5.2 必须保留的选择元数据

统一执行身份不等于删除采样来源信息。每笔订单必须记录：

```text
decision_authority=model|ensemble
selection_reason=policy_exploitation|coverage_sampling
production_permission=false
primary_model_id
primary_model_version
participating_model_ids
model_lifecycle_states
decision_id
prediction_horizon
direction
selection_probability
candidate_rank
market_regime
risk_policy_version
```

其中：

- `selection_reason` 仅用于审计、训练去偏、覆盖率分析和样本权重。
- `selection_reason` 不得触发另一套执行合同。
- `selection_probability` 用于识别系统主动选择造成的样本偏差。
- `decision_authority` 必须准确表示最终方向由单模型还是统一决策层产生，不能写成模糊默认值。

历史 `paper_exploration` 和 `paper_training` 订单只保留只读解析和历史展示能力，不保留可执行兼容分支，也不得被自动改写成新订单身份。

## 6. 统一决策层整改

### 6.1 可参与决策的模型输出

统一决策层只能接收当次决策中满足以下条件的输出：

- 输出时间在有效窗口内。
- 模型制品可加载且版本明确。
- 输入特征与市场时间一致。
- 输出能解析为 long、short 或明确 HOLD。
- 预测期限完整。
- 来源和调用链可以审计。

过期、解析失败、缺少关键特征或来源不明的输出只能记录为诊断，不得参与权重或投票。

### 6.2 模型与专家的职责边界

未晋升模型可以成为模拟盘方向主体。专家的职责调整为：

- 提供独立支持或反对证据。
- 识别数据异常、流动性风险、极端事件和明显方向冲突。
- 调整置信度和仓位建议。
- 在存在明确强反向证据或硬风险时阻断。

专家不得继续拥有以下隐式否决权：

- 要求至少两个 LLM 专家同向赞成才能模拟盘交易。
- 把全部 HOLD 自动解释为否决模型方向。
- 把未晋升或 production 证据不足解释为 HOLD。
- 把同一底层模型的多个角色当作多个独立证据源。

### 6.3 模拟盘方向合同

模拟盘方向可以由以下任一方式成立：

1. 一个可审计模型给出明确方向，且不存在明确强反向证据。
2. 多模型聚合后形成明确方向，且去相关后的净支持超过配置阈值。
3. 主模型方向明确，专家只提供风险修正或减仓建议。

以下情况拒绝：

- 没有模型给出明确方向。
- 多空冲突达到不可判定程度。
- 输入或输出事实无效。
- 出现明确硬风险。

## 7. 模拟盘机会选择与覆盖采样

### 7.1 普通择优

普通模拟盘候选可以使用以下质量条件排序：

- 方向明确。
- 最低预测置信度达标。
- 综合评分达标。
- 没有严重专家冲突。
- 扣除估算成本后的预期收益较好。
- 当前币种、方向和市场状态不过度重复。

“预计收益覆盖成本”可以作为普通择优条件，但不得成为所有模拟盘订单的全局硬门槛，否则当所有模型尚未校准时会再次形成无交易循环。

### 7.2 覆盖采样

当存在方向明确、事实有效、硬风险通过的候选，但所有候选都未达到普通择优标准时，可以从同一 `normal_strategy_trade` 主链选择受控覆盖样本。

覆盖采样必须满足：

- 只运行在 OKX 模拟盘。
- 不要求收益 LCB 为正。
- 不要求 Profit Factor 成熟。
- 不要求 production 样本数量。
- 不要求专家同向多数票。
- 使用更小的单笔风险和组合风险。
- 优先补足币种、方向、预测期限和市场状态的样本缺口。
- 对最近已采样的相似候选去重。
- 记录选择概率和覆盖原因。
- 与普通择优订单共用执行、持仓、平仓和结算合同。

覆盖采样不是随机乱开仓。没有明确方向、事实无效或硬风险失败时仍然不能下单。

### 7.3 活性要求

系统必须区分“市场上没有合格方向”和“代码合同系统性阻断”：

- 若滚动观察窗口内没有任何明确方向，0 开仓可以是正常结果。
- 若持续存在明确方向、账户容量和硬风险均正常，但 30 分钟仍为 0 开仓，必须生成结构化活性告警。
- 告警应聚合每层拒绝原因，显示最主要的阻断合同和候选数量。
- 不允许用“等待晋升”“production 证据不足”解释模拟盘 0 开仓。
- 若所有候选因最小下单量或风险预算冲突而拒绝，应单独报告容量配置错误，不能伪装成策略 HOLD。

活性告警用于发现系统问题，不直接强制制造订单。

## 8. 仓位、最小下单量与组合风险

### 8.1 模拟盘仓位原则

- 未晋升模型默认使用受控的小风险仓位。
- 模型建议不能直接决定最终仓位或杠杆。
- 风险引擎可以减小仓位、降低杠杆或拒绝订单。
- 不因亏损历史完全取消模型训练资格，可降低其影响和风险预算。
- 不使用生产收益分布作为模拟盘 sizing 的必需输入。

### 8.2 最小下单量冲突

仓位计算必须先读取 OKX 权威合约规格，再处理最小合约数量和步长：

1. 计算风险预算允许的最大合约数量。
2. 按 OKX 步长向下取整。
3. 检查结果是否达到 OKX 最小下单数量。
4. 若最小订单本身会突破单笔或组合风险，不得静默向上取整，必须拒绝并记录 `paper_min_order_exceeds_risk_budget`。
5. 若大量候选持续触发该原因，应调整模拟盘风险参数或候选合约范围，而不是绕过风险合同。

Dashboard 和活性报告必须区分：

- 策略没有方向。
- 质量筛选未通过。
- 最小下单量不足。
- 单笔风险不足以承载最小订单。
- 组合容量已满。

### 8.3 初始风险策略

具体数值应由现有账户权益、OKX 合约规格和当前组合上限计算后确定，不在本文中硬编码。初始策略至少包含：

- 普通择优单笔风险上限。
- 覆盖采样单笔风险上限。
- 全部覆盖采样组合风险上限。
- 单币种和同方向暴露上限。
- 最大同时持仓数。
- 相似候选冷却时间。
- 极端波动暂停条件。

上线前必须证明该配置能够覆盖至少一组合规 OKX 最小订单，否则“允许模拟盘交易”仍会被仓位合同实际锁死。

## 9. 执行、持仓和平仓

### 9.1 执行合同

新模拟盘执行合同只验证：

- `trade_mode=paper`。
- `entry_type=normal_strategy_trade`。
- `production_permission=false`。
- 方向、身份、价格、数量和风险证据完整。
- OKX demo 账户和合约规格有效。
- 不存在重复订单或容量冲突。
- 保护策略完整。

不得再次验证：

- 晋升状态。
- 收益 LCB。
- Profit Factor。
- production source count。
- production execution-cost distribution。
- `paper_exploration` 信息价值。

### 9.2 持仓管理

所有模拟盘持仓统一进入正常动态管理：

- 硬止损。
- 动态止盈。
- 延续性恶化退出。
- 模型压力和反向证据退出。
- 部分平仓和剩余仓位管理。
- 最大持仓时间保护。
- 组合风险主动收缩。

预测期限到期只生成训练观察和 Shadow 标签，不得仅因 10/30/60 分钟标签到期强制真实平仓。真实平仓必须由正常持仓策略或硬风险触发。

### 9.3 权威事实

订单创建、成交、持仓和平仓必须保留完整血缘：

```text
analysis_id
decision_id
order_id
OKX ordId
OKX tradeId 集合
position_id
entry and exit fills
fee
funding
slippage
contract specification
settlement identity
```

本地 execution result 只可用于运行态恢复，不能冒充 OKX 权威成交或训练事实。

## 10. 训练数据路由

### 10.1 可进入交易结果训练集

只要 OKX 权威结算事实完整，模拟盘结果都应进入训练：

- 盈利交易作为正向结果。
- 亏损交易作为负向结果。
- 成本吞噬收益作为执行和盈利质量结果。
- 方向正确但退出错误作为分阶段归因结果。
- 部分平仓按完整仓位生命周期汇总，同时保留分段事实。

亏损本身不是隔离理由。

### 10.2 分层样本类型

不同事实必须进入不同训练或诊断任务：

| 事实类型 | 数据用途 | 是否作为真实盈亏标签 |
| --- | --- | --- |
| OKX 权威结算的盈利交易 | 方向、收益、退出、成本训练 | 是 |
| OKX 权威结算的亏损交易 | 方向、风险、退出、成本训练 | 是 |
| 未成交订单 | 执行概率、流动性和报价诊断 | 否 |
| 被硬风控拒绝的决策 | 风险策略和 Shadow 评估 | 否 |
| 未被选择的候选 | Shadow 10/30/60 分钟机会成本 | 否 |
| 成交或费用事实不完整 | 隔离和事实恢复 | 否 |

### 10.3 隔离条件

只有以下情况才隔离真实交易结果：

- 订单身份无法对应。
- 成交行不完整或无法去重。
- 合约规格缺失或不可信。
- 入场或出场成交数量无法闭合。
- 手续费事实缺失。
- 按持仓周期本应存在的资金费事实无法确认。
- 滑点所需权威标记价格缺失。
- 部分平仓后的剩余仓位无法闭合。
- 权威平仓和本地生命周期无法匹配。

必须区分“合法的零资金费”和“资金费事实缺失”，不得把数值 0 自动解释为缺失或完整。

### 10.4 样本权重与选择偏差

- OKX demo 权威结算样本是模拟盘训练的核心真实样本。
- 普通择优和覆盖采样可以进入同一训练体系，但必须保留 `selection_reason`。
- 训练时应使用选择概率、市场覆盖和相似样本密度修正主动采样偏差。
- production、paper、shadow 和 rejected-decision 来源必须分开统计。
- Shadow 标签可作为辅助学习，不得冒充真实成交成本和真实结算结果。
- 不得因 `coverage_sampling` 自动将样本降为不可训练；是否可训练只取决于事实合同和对应训练任务。

## 11. 推荐主路由

```python
if trading_mode == "paper":
    decision = ensemble.combine(eligible_model_outputs)

    if not decision.has_direction:
        return reject("no_direction")

    selection = paper_selector.select(
        decision=decision,
        allow_coverage_sampling=True,
    )

    if not selection.selected:
        return reject(selection.reason)

    risk = paper_risk_engine.evaluate(decision, selection)
    if not risk.allowed:
        return reject(risk.reason)

    return execution_service.open_normal_strategy_trade(
        decision=decision,
        selection_reason=selection.reason,
        production_permission=False,
    )

if trading_mode == "live":
    permission = production_trade_gate.evaluate(
        decision=decision,
        live_ml_ready=model.live_ml_ready,
    )

    if not permission.allowed:
        return reject(permission.reason)

    risk = live_risk_engine.evaluate(decision)
    if not risk.allowed:
        return reject(risk.reason)

    return execution_service.open_live_trade(decision)
```

该伪代码表达权限边界，不要求实际实现必须采用相同函数名。

## 18. 模拟盘权限整改结论

本方案接受用户建议的核心方向，并加入以下必要修正：

- 模拟盘取消晋升和生产统计门槛。
- 模拟盘执行身份统一为正常策略交易。
- 未晋升模型可以成为决策主体，专家 HOLD 不再拥有隐式否决权。
- 普通择优与覆盖采样共用一条执行链，只保留选择原因用于审计和训练去偏。
- 预计收益覆盖成本不作为所有模拟盘订单的全局硬门槛。
- 亏损交易正常训练，未成交和拒单按独立任务保存。
- 新闻缺失不作为通用硬门槛。
- 模型表现降级与系统数据失效必须分开处理。
- 所有生产晋升和 `live_ml_ready` 检查严格限定在 OKX 实盘路径。

整改后的系统不承诺模型会立即盈利，但必须保证：模型能够持续产生真实、完整、可归因的模拟盘交易样本；亏损不会阻断学习；生产权限不会被模拟盘放宽；系统也不会再因等待晋升而无限期停止采样。

## 19. 训练体系整改目标

模拟盘权限放开只能解决“没有真实交易样本”的问题，不能单独保证训练标签正确。训练体系必须同时解决：

- 没有成交的市场机会也能形成方向和收益标签。
- 真实成交结果能够学习费用、滑点、成交概率和策略实际收益。
- 入场质量不被不断变化的退出策略污染。
- 小样本阶段不进行无效的币种级或市场状态级拆模。
- 训练、验证、测试之间不存在时间泄漏和决策组泄漏。
- 新 Artifact 在后台生成、独立验证并原子切换，不修改交易进程正在使用的模型。
- 盈利、亏损、尾部风险和高置信度错误都能进入受控训练体系。
- LLM、数值模型、提示词和检索记忆使用不同更新节奏。
- 晋升按相互独立的决策组和多个市场状态评估，不按高度相关的数据行堆数量。

目标训练闭环：

```text
每次市场分析
-> 保存 point-in-time 特征和全部模型输出
-> 生成多个固定时间窗的市场标签
-> 若实际下单，则等待 OKX 权威成交与结算
-> 分别进入市场标签、真实交易、执行诊断和拒单/Shadow 数据集
-> 按 decision_group 和时间隔离训练
-> 后台生成 Candidate Artifact
-> 独立验证、校准和分市场状态评估
-> Challenger 与当前 Paper Champion 比较
-> 原子晋升、保持当前版本或自动回滚
-> 独立评估是否获得 OKX 实盘候选资格
```

## 20. 同时建设两类核心训练数据

### 20.1 数据分类

| 数据类型 | 来源 | 主要用途 |
| --- | --- | --- |
| 市场标签样本 | 每次分析之后的未来行情路径 | 训练方向、机会、收益分布、MFE、MAE 和尾部风险 |
| 模拟盘成交样本 | OKX 模拟盘完整成交、持仓与权威结算 | 训练费用、滑点、成交概率、退出质量和策略实际收益 |

两类数据必须同时建设，不能只依赖实际成交：

- 只使用成交样本会让模型只看到系统已经选择的机会，产生严重选择偏差。
- 只使用市场标签无法学习真实成交概率、手续费、滑点、资金费、冲击成本和持仓执行偏差。
- 市场标签用于回答“当时市场后来怎样”。
- 成交样本用于回答“系统实际做了什么，以及最终付出了什么成本”。

### 20.2 每次分析后的市场标签

每个完成的市场分析，不论是否开仓，都应在未来时间窗成熟后生成标签。目标新合同至少支持：

- 5 分钟收益。
- 15 分钟收益。
- 60 分钟收益。
- 240 分钟收益。
- 各时间窗 MFE，即最大有利变动。
- 各时间窗 MAE，即最大不利变动。
- long 扣除当时可得估算成本后的反事实收益。
- short 扣除当时可得估算成本后的反事实收益。
- 固定规则下是否触发止损。
- 固定规则下是否先触发止盈或止损。
- 标签窗口内的波动、流动性和市场状态变化。

当前已有 10/30/60 分钟 Shadow 结果。在迁移期间可以继续保留为历史和辅助标签，但新训练合同必须明确使用哪一组时间窗；不同标签版本不得在没有 manifest 说明的情况下混合训练。

### 20.3 市场标签不等于真实成交

市场标签必须明确标记为 counterfactual/shadow，不得冒充：

- 实际成交价。
- 实际手续费。
- 实际滑点。
- 实际资金费。
- 实际持仓路径。
- 实际策略收益。

反事实 long/short 收益只能使用决策时可见的入场价格规则和当时的估算成本模型。真实交易结果只能来自 OKX 权威成交与结算。

## 21. 版本化标签合同

### 21.1 标签合同必须固定的内容

每条训练标签必须携带 `label_contract_version`，并能复算以下内容：

- 决策发生时间。
- 标签窗口起点和终点。
- 入场参考价格类型及来源。
- K 线或逐笔价格的完成状态。
- long/short 收益公式。
- MFE/MAE 计算方式。
- 估算费用、滑点和冲击成本版本。
- 止损、止盈和先后触发规则。
- 尾部亏损阈值。
- 缺失价格点和异常行情的处理规则。
- 是否存在交易暂停、插针或流动性中断。

### 21.2 未成交机会的止损标签

未成交机会的“是否触发止损”不能事后主观判断。必须使用版本固定的反事实规则：

1. 使用决策时已经存在的可执行参考价格作为虚拟入场价格。
2. 使用当次策略版本保存的止损距离。
3. 使用完整的未来价格路径判断触发顺序。
4. 同一根 K 线同时越过止盈和止损但无法知道先后时，标记为路径不确定，不得强行选择有利结果。
5. 任何规则变化都创建新标签版本，不回写旧标签语义。

### 21.3 标签成熟度

- 5 分钟窗口只有在完整 5 分钟未来行情存在后成熟。
- 240 分钟窗口不能提前使用短窗口结果代替。
- 未成熟标签不得进入训练。
- 部分成熟的多任务行可以仅训练已经成熟的任务，但 manifest 必须记录每个任务的有效样本数。
- 训练触发中的“新增完整结果”应按目标任务的成熟 `decision_group` 计算，不能只按数据库新增行数。

## 22. 分离机会、入场、退出和执行任务

### 22.1 机会模型

目标：预测固定时间窗内市场本身是否存在上涨、下跌和尾部风险空间。

主要输入：

- 决策时 point-in-time 行情特征。
- 波动率、流动性、成交量和市场状态。
- 决策时已经发布且可见的事件特征。

主要标签：

- 固定时间窗 long/short 原始收益。
- MFE/MAE。
- 收益分位数。
- 尾部亏损概率。

机会模型不使用系统最终是否开仓作为方向标签，也不直接使用动态退出后的最终结算收益。

### 22.2 入场模型

目标：在当前价格、估算成本、风险和机会分布下判断是否值得入场。

主要输入：

- 机会模型输出。
- 实时价差、流动性和成本估计。
- 当前账户容量、组合暴露和市场状态。
- 候选方向、预测期限和入场有效窗口。

主要标签：

- 固定窗口扣除估算成本后的机会收益。
- 入场之后的短期 MFE/MAE。
- 入场时机相对于窗口内可执行价格的质量。

入场模型不能简单把最终成交净收益作为唯一标签，因为最终收益同时受到退出策略和执行结果影响。

### 22.3 退出模型

目标：持仓建立后判断继续持有、减仓或平仓。

主要输入：

- 入场后的新行情和持仓路径。
- 当前未实现盈亏、MFE/MAE 和已持有时间。
- 市场状态变化和反向证据。
- 剩余风险预算和退出成本。

主要标签：

- 在各个持仓时点继续持有、减仓或退出的后续费后结果。
- 真实部分平仓和最终结算。
- 相同持仓状态下不同退出时间的反事实结果。

退出训练必须识别截尾样本：

- 尚未平仓的持仓不能当成零收益结束。
- 因硬风控、账户异常或交易所故障退出的样本必须保留退出原因。
- 动态退出规则变更后，旧样本仍保留原策略版本，不重写历史决策语义。

### 22.4 执行模型

目标：预测成交概率、手续费、滑点、冲击成本和订单执行风险。

主要输入：

- 合约规格。
- 订单方向、类型和数量。
- 决策时盘口、价差、深度和波动率。
- 下单时段、流动性和市场状态。

主要标签：

- 是否成交和成交耗时。
- 部分成交比例。
- 实际手续费。
- 相对权威标记价格的实际滑点。
- 实际冲击成本。
- 撤单、拒单和交易所错误类型。

未成交订单只能用于执行模型或诊断，不能作为真实策略盈亏标签。

### 22.5 小样本阶段的实现边界

任务分离首先意味着分离标签、数据集、评估指标和 Artifact 责任，不要求冷启动阶段立即训练四套大型独立模型。样本不足时可以：

- 共享 point-in-time 特征管线。
- 使用一个共享骨干输出多个任务头。
- 使用简单独立基线分别验证任务可学性。
- 在 manifest 中分别记录各任务样本数和指标。

不得因为共享模型实现而重新把所有任务压缩成一个最终盈亏标签。

## 23. 多任务预测合同

### 23.1 最低结构化输出

每个候选方向至少输出：

```text
expected_net_return_pct
return_q10
return_q50
return_q90
loss_probability
tail_loss_probability
expected_execution_cost_pct
expected_mfe_pct
expected_mae_pct
prediction_horizon
model_version
calibration_version
```

最终交易决策由确定性代码组合这些结果。LLM 的自报置信度不能直接作为概率使用，除非它已经通过独立时间外样本校准并保存校准版本。

### 23.2 数值语义

- `expected_net_return_pct` 必须明确为已经扣除 `expected_execution_cost_pct` 后的收益，避免决策层重复扣费。
- 同时保留 gross return 预测时，应使用独立字段，禁止同名混用。
- `return_q10 <= return_q50 <= return_q90`，任何违反分位数单调性的结果均不可直接用于交易。
- `tail_loss_probability` 必须绑定明确的尾部阈值和预测期限。
- `expected_mfe_pct` 和 `expected_mae_pct` 必须使用与方向一致的符号和口径。
- 多时间窗输出必须标记 horizon，不能把 5 分钟和 4 小时预测聚合成一个无期限置信度。

### 23.3 校准

- 概率校准只能使用时间外预测结果。
- 校准器只能在训练窗口拟合，并应用于之后的验证或测试窗口。
- 样本不足时优先使用全局校准，不按币种分别校准。
- 按市场状态展示校准误差，但小样本状态不单独拟合校准器。
- Artifact 必须同时保存原始概率、校准概率、校准方法和校准数据边界。

## 24. 小样本冷启动策略

### 24.1 全市场共享模型

当前完整权威样本规模不足以稳定训练多套币种、方向或市场状态模型。冷启动阶段应：

- 所有币种共享一个全局模型。
- 将波动率、流动性、成交量、价差、市场状态和资产类别作为特征。
- long/short 可以使用统一模型加方向字段，或使用对称变换后的方向特征。
- 暂不按单币种训练独立模型。
- 暂不按 regime 训练独立模型。
- 暂不因增加树数量而宣称模型能力提升。

币种 ID 可以作为受控特征或评估分组，但不能成为模型记忆单个币种历史的主要方式。应优先使用能够跨币种迁移的市场属性。

### 24.2 模型优先级

冷启动阶段优先建立可解释基线：

- Ridge/Elastic Net。
- 稳健线性回归。
- Logistic Regression。
- Quantile Regression。
- 浅层决策树或受严格约束的随机森林。
- 受控深度和叶节点下限的 ExtraTrees 基线。

ExtraTrees 和随机森林仍可能在几十个独立决策组上过拟合。所有复杂模型必须与简单基线进行同一时间外测试比较，不能只比较训练集指标。

### 24.3 何时允许拆模

只有满足以下条件才考虑按方向、市场状态或资产类型拆分：

- 每个子组拥有足够的独立 `decision_group`。
- 子组跨多个时间窗口和行情阶段。
- 拆分模型在严格时间外测试中稳定优于全局模型。
- 改善不是由单个币种或单次行情主导。
- 拆分后概率校准和尾部风险仍可验证。

## 25. 训练触发与 Artifact 生命周期

### 25.1 训练触发条件

不应每完成一笔交易就重新训练。推荐触发条件：

```text
新增成熟且完整的独立 decision_group >= batch_threshold
or
(新增成熟 decision_group >= minimum_increment
 and 距离上次成功训练 >= 24 小时)
or
(检测到特征或收益分布漂移
 and 新增成熟 decision_group >= drift_minimum_increment)
```

初始建议可以从 `batch_threshold=50` 开始，但最终值必须根据有效独立组数量、标签期限和模型复杂度确定。

以下情况不得启动无意义重训：

- 只有时间超过 24 小时但没有新增成熟标签。
- 新增的只是重复行或同一 decision_group 的相关币种结果。
- 新增结果事实不完整。
- 只有未成熟的 4 小时标签。
- 只有市场分布漂移但没有足够新标签可供学习。

发生漂移但缺少新标签时，应优先：

- 降低模型影响权重。
- 切换到稳健基线。
- 收紧仓位。
- 保持模拟盘采样。
- 等待标签成熟后再训练。

### 25.2 Artifact 角色

推荐保留：

- `paper_champion`：当前模拟盘主模型。
- `paper_challenger`：后台新训练候选。
- `rollback_model`：上一个经过验证的稳定版本。

Artifact 训练和切换要求：

- 后台独立生成 Candidate Artifact。
- 交易进程预测期间不修改当前模型文件。
- 完整写入训练 manifest、特征合同、标签合同和数据时间边界。
- 加载并验证新 Artifact 后原子切换指针。
- 切换失败时继续使用当前 champion。
- Challenger 表现不达标时拒绝切换，但继续允许未来重新训练。
- Champion 运行态异常或显著退化时自动回滚到 `rollback_model`。
- 回滚不恢复已经删除的旧执行合同或旧特征格式。

### 25.3 Manifest 最低内容

- Artifact ID 和模型版本。
- 训练代码版本。
- 特征合同版本。
- 标签合同版本。
- 训练、验证、测试时间边界。
- purge 和 embargo 边界。
- decision_group 数量与数据行数。
- 各任务有效样本数量。
- 各样本来源数量。
- 样本权重和时间衰减规则。
- 市场状态覆盖。
- 超参数和随机种子。
- 原始及校准后指标。
- 当前 champion、challenger 和 rollback 关系。

## 26. 严格时间序列验证

### 26.1 推荐划分

```text
训练窗口
-> purge 间隔
-> 验证窗口
-> embargo 间隔
-> 测试窗口
```

必须按 `decision_group` 切分：同一轮市场扫描产生的 BTC、ETH 和其他币种结果高度相关，不能作为多个完全独立样本随机分散到训练集和测试集。

### 26.2 Purge 与 Embargo

- 训练样本的标签结束时间必须严格早于验证决策起点。
- purge 长度至少覆盖当前训练任务使用的最大标签期限。
- 使用 240 分钟标签时，不能用短于 240 分钟的 purge 假装时间互斥。
- embargo 用于减少相邻窗口间的持仓路径、特征和事件重叠。
- purge 和 embargo 的实际时间边界必须写入 manifest。

### 26.3 禁止的数据泄漏

- 使用预测时刻之后发布的新闻或修订数据。
- 使用尚未完成的 K 线作为已完成特征。
- 使用最终成交价或平仓结果构造入场特征。
- 在全量数据上预先拟合标准化器、缺失值填充器或特征选择器。
- 同一个持仓生命周期同时出现在训练和测试中。
- 同一 decision_group 的不同币种分散到不同集合。
- 使用测试集选择超参数、概率校准器或晋升阈值。
- 在回测时读取后来才写入的 LLM 检索记忆。

所有预处理器必须只在训练窗口拟合，然后冻结应用到验证和测试窗口。

### 26.4 验证方式

- 使用滚动或扩展窗口 walk-forward 验证。
- 保存每个时间折的指标，不只保存合并总指标。
- 展示各折波动和最差折结果。
- 概率校准和模型选择不能复用最终测试窗口。
- 最终测试集只在 Candidate 完成全部选择后使用一次。

## 27. 按市场状态评估

### 27.1 最低评估维度

每次预测必须记录 `market_regime`，至少支持以下评估分组：

- 趋势/震荡。
- 高波动/低波动。
- 高流动性/低流动性。
- long/short。
- 主流币/小币种。
- 有新闻冲击/无新闻冲击。

市场状态定义必须版本化，并且只使用决策时可见信息。

### 27.2 小样本处理

- 小样本阶段将 regime 用作特征和评估维度，不训练多个独立 regime 模型。
- 每个分组同时展示数据行数、独立 decision_group 数和置信区间。
- 样本不足的分组标记为证据不足，不得强行得出盈利或亏损结论。
- 晋升不机械要求所有极小分组都盈利。
- 主要市场状态必须具有足够覆盖，且不得存在有统计意义的灾难性子组。

新闻冲击标签必须根据事件发布时间和当时可见性生成，不能使用事后新闻归类污染历史预测。

## 28. 受控样本重放池

### 28.1 重放池组成

训练集不能只保留最近盈利交易，也不能简单让盈亏各占 50%。重放池应覆盖：

- 最近样本，用于适应市场变化。
- 历史代表性样本，用于避免灾难性遗忘。
- 高波动和尾部亏损样本。
- 不同方向、币种和市场状态。
- 被模型高置信度判断错误的困难样本。
- 成本吞噬预期收益的执行困难样本。

### 28.2 权重规则

- 最近样本可以获得较大权重。
- 旧数据权重随时间逐渐衰减，但不能自动降为零。
- 尾部风险和困难样本可以适度增权。
- 同一事件、同一持仓生命周期和高度相似样本必须去重或限制总权重。
- 不通过复制数据行制造类别平衡或虚假样本数量。
- 所有样本权重、衰减函数、重放原因和去重规则必须写入 manifest。
- 同时报告原始样本量与加权后的有效样本量。

### 28.3 验证集隔离

重放池只用于训练窗口。验证集和测试集必须保持自然时间分布，不允许：

- 重采样盈利或亏损比例。
- 加入未来困难样本。
- 复制尾部事件。
- 根据测试表现修改样本权重。

## 29. LLM 与数值模型分层更新

### 29.1 更新节奏

| 层级 | 推荐更新方式 |
| --- | --- |
| Local ML / Quant API | 每日满足最小新增批量后，或达到完整结果批次后训练 |
| 交易检索记忆 | 权威结果完成后增量更新 |
| LLM SFT/DPO/LoRA | 累计数百条高质量、去重、事实完整样本后低频训练 |
| 提示词与结构化协议 | 独立版本管理、独立回归和灰度验证 |

BB-FinQuant-Expert-14B 不应每几十笔交易就重新 LoRA。频繁微调会造成：

- 小样本过拟合。
- 遗忘通用能力。
- 训练结果难以复现。
- 提示词、检索和权重变化无法归因。
- 交易运行态频繁切换。

### 29.2 LLM 职责

LLM 主要负责：

- 事件解释。
- 新闻与市场叙事归纳。
- 风险因素识别。
- 结构化支持和反对证据。
- 异常情景分析。

数值模型和确定性代码主要负责：

- 收益分布预测。
- 概率和分位数校准。
- 执行成本估计。
- 仓位和杠杆裁剪。
- 组合风险。
- 最终交易合同。

### 29.3 检索记忆边界

交易系统的版本化检索记忆与项目 Hindsight 必须隔离：

- 项目 Hindsight 用于保存架构决策、修复和运维知识。
- 交易检索库用于模型可用的历史事件和权威结果。
- 未完成结算的交易不能写入结果型检索记忆。
- 写入内容必须携带事件时间、可见时间、来源和版本。
- 历史回测只能读取当时已经存在的记忆快照。
- 不得让后来结算结果泄漏到过去的决策重放。

## 30. 实盘晋升评价

### 30.1 晋升前提

模拟盘模型可以持续正常交易，但晋升到 OKX 实盘候选至少应同时评估：

- 独立测试集费后收益为正。
- 收益 LCB 为正。
- Profit Factor 达到阈值。
- 最大回撤达标。
- 尾部风险达标。
- 概率经过时间外校准。
- 覆盖多个主要市场状态。
- 连续多个时间窗口没有明显退化。
- 执行成本和滑点事实完整。
- 没有关键数据合同或模型制品异常。

### 30.2 独立样本口径

- 晋升主要按独立 `decision_group` 统计，不按交易行数统计。
- 同一扫描产生的多币种交易不能被当成多次完全独立证明。
- 同一市场事件下的多笔相关交易必须识别聚类相关性。
- 同时报告交易笔数、decision_group 数、市场事件数和有效样本量。
- 30 笔高度相关交易不能自动满足晋升证据要求。

### 30.3 指标解释

- Profit Factor 点估计 `> 1` 只能作为最低方向性条件，不能单独授权晋升。
- 应同时评估 Profit Factor 和收益估计的不确定性。
- LCB、回撤、校准和市场覆盖必须来自严格留出集。
- 阈值按策略期限、风险预算和执行成本版本管理，不能散落硬编码。
- 多个 Candidate 同时比较时，应考虑多重选择造成的乐观偏差。
- 最差时间折和灾难性市场子组必须单独展示。

### 30.4 晋升不等于自动实盘下单

晋升只授予实盘候选资格。即使模型处于 Active：

- 每笔 live 决策仍须通过 `production_trade_gate`。
- 每笔订单仍须通过账户、流动性、仓位和组合风险。
- `live_ml_ready=false` 时必须失败关闭。
- 运行态退化时应撤销 live 权限，但继续保留 paper 分析、交易和训练能力。

### 32.4 训练器

- 预处理器仅在训练窗口拟合。

- 在后台生成 challenger，不修改正在运行的 champion。

### 32.5 Artifact 注册与晋升

- 市场标签样本和真实成交样本数量。
- 数据行数与独立 decision_group 数。
- 各时间窗成熟/未成熟标签数量。
- 各任务有效训练样本数量。

## 34. 训练线上验收标准

### 34.1 市场标签

- 每次有效分析都有唯一 decision_group 和 point-in-time 特征快照。
- 未开仓分析能够持续生成成熟的多时间窗标签。
- 标签生成不要求模型晋升或实际成交。
- 标签时间、价格、成本和止损规则可以复算。
- 未来数据和未完成 K 线泄漏数量为 0。

### 34.2 真实交易样本

- 新模拟盘订单完成后能形成 OKX 权威结算样本。
- 盈利和亏损完整样本均进入正确训练任务。
- 未成交和拒单不会进入真实盈亏标签。
- 手续费、滑点、资金费和持仓数量能够闭合。
- 事实缺失只产生明确隔离原因，不生成默认标签。

### 34.3 训练运行态

- 训练只在满足独立决策组触发条件时运行。
- 后台训练不阻塞市场分析和交易。
- 当前 champion 在训练期间保持只读。
- Candidate Artifact 包含完整 manifest 和时间分区报告。
- 切换和回滚均为原子操作。
- 正常样本等待不记录为训练故障。

### 34.4 模型质量

- 简单基线与候选模型在相同时间外集合比较。
- 同时报告净收益、分位数、损失概率、校准、MFE/MAE 和尾部风险。
- 按主要 market regime 展示表现和有效样本量。
- 不用训练集表现或一次回测直接授权实盘。
- 晋升失败不阻断模拟盘持续采样和下一轮训练。

## 35. 整体最终结论

交易权限整改和训练体系整改必须作为同一个闭环实施：

1. 模型晋升只控制 OKX 实盘权限，不控制 OKX 模拟盘交易。
2. 所有可用模型持续产生分析、市场标签和模拟盘候选。
3. 模拟盘订单统一走正常交易、持仓、结算和训练链。
4. 普通择优和覆盖采样共用执行合同，但保留选择原因用于训练去偏。
5. 每次分析都生成未来市场标签，避免只学习被系统选中的成交机会。
6. 机会、入场、退出和执行使用独立标签与评估责任。
7. 数值模型输出收益分布、损失概率、成本和 MFE/MAE，确定性代码负责最终组合和风险。
8. 小样本阶段使用全市场共享简单模型，不按币种或市场状态过早拆分。
9. 训练按新增独立 decision_group、时间和漂移触发，在后台生成 Challenger 并原子切换。
10. 所有验证严格遵守 point-in-time、decision_group、purge、embargo 和时间外校准。
11. 训练重放保留近期、代表性、尾部和困难样本，所有权重写入 manifest。
12. LLM 低频微调，交易检索记忆、项目记忆、数值模型和提示词分别管理。
13. 盈利和亏损权威结果都用于训练；未成交、拒单和 Shadow 按独立任务保存。
14. 实盘晋升按独立决策组、多个时间窗口、市场状态、校准和尾部风险共同评价。
15. 晋升只授予实盘候选资格，任何 live 订单仍需逐笔生产门禁。

最终系统不以“快速制造盈利证明”为目标，而是建立不会因晋升门槛停止采样、不会因选择偏差误导模型、不会因退出规则变化污染入场标签、能够持续产生可复算证据的训练与交易闭环。
