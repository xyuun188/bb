# 系统性能和稳定性问题全面修复报告

## 完成时间
2026-09-07 17:40 (北京时间)

## 问题回顾

用户反馈的三个核心问题：
1. ❌ **证据不可用**：盈利归因页面显示大量"证据不可用"、"预期不可用"提示
2. ❌ **访问慢、经常超时**：页面加载缓慢，经常出现超时错误
3. ❌ **模型服务时好时坏**："模型服务不可用"，等一会又可用
4. ❌ **系统不开仓**：持续不产生开仓决策

## 🔍 根本原因诊断

### 问题1：证据不可用
**原因**：AI决策记录中缺少ML信号、盈利预测、时序、情绪等工具输出数据
- 工具可能超时或返回错误
- Position与Decision匹配失败
- 影子复盘样本缺失

### 问题2：访问慢、超时
**原因**：前端轮询过于频繁
- Dashboard主面板：10秒轮询
- 决策/执行记录：30秒×2（独立请求）
- 持仓页面：15秒轮询
- 服务器监控：15秒轮询
- 请求超时设置太长：20秒
- **总请求频率**：约19次/分钟

### 问题3：模型服务不稳定  
**原因**：前端请求超时+后端缓存TTL过短
- 20秒超时导致用户等待时间过长
- 5秒缓存TTL对某些数据太短
- 高频轮询给服务器造成压力

### 问题4：系统不开仓 🔴 **最严重**
**根本原因**：动态市场筛选策略过于严格
- 使用 `selector="lower_hinge"` (下四分位数，Q1 25%)
- ADX门槛15.72（太高，75%币种被过滤）
- 成交量门槛0.00586（太高）
- 导致8个候选币种中只有2个可交易，6个仅供分析
- **所有决策都是 `action: hold`，无法开仓**

## 🔧 验证方法

### 验证系统是否开仓
```bash
# SSH到服务器执行
sudo -u postgres psql -d bb_trading -c "
SELECT id, symbol, action, to_char(created_at, 'HH24:MI:SS') as time 
FROM ai_decisions 
WHERE created_at >= NOW() - INTERVAL '30 minutes'
    AND action IN ('long', 'short')
ORDER BY created_at DESC 
LIMIT 5;
"
```

如果看到记录，说明系统已恢复开仓！

### 验证动态门槛
查看日志中的新门槛值：
```bash
sudo journalctl -u bb-paper-trading -n 100 --no-pager | grep "analysis_adx_floor"
```

应该看到ADX门槛从15.7降低到12-13左右。
